iLogic Parameters: Complete Guide to
Driving Your Autodesk Inventor Model

Parameters are the backbone of every iLogic rule. Every dimension, material, configuration, and calculation in Autodesk Inventor is controlled through parameters — and iLogic gives you full read/write access to all of them. This guide covers everything you need to know.

What Are iLogic Parameters?

In Autodesk Inventor, parameters are named values that control your model — dimensions, angles, quantities, material names, configuration flags. Every number driving your geometry is stored as a parameter.

iLogic lets you read these parameters (to make decisions) and write them (to change the model). This is the core of every automation rule: read some inputs, do some logic, update some parameters.

💡 Think of parameters as variables your model lives in. When you change a parameter value, Inventor rebuilds the model automatically to match.

How to Read a Parameter in iLogic

To read a parameter, use the Parameter() function or simply reference the parameter name directly in your rule:

' Method 1: Reference directly by name (most common) Dim length As Double = Parameter("Length") ' Method 2: Direct name reference (works when parameter name has no spaces) Dim width As Double = Width ' Read a parameter and use it in a calculation Dim area As Double = Parameter("Length") * Parameter("Width") iLogicVb.SetParameter("Area", area)

⚠️ Parameter names are case-sensitive. Length and length are different parameters. Always match the exact name from your Parameters panel.

How to Write / Change a Parameter

To change a parameter value and update the model, assign a new value using the parameter name:

' Directly assign a new value to a parameter Parameter("Length") = 500 ' Or use the full method iLogicVb.SetParameter("Length", 500) ' Set based on a condition If Parameter("LoadRating") > 5000 Then Parameter("PlateThickness") = 20 Else Parameter("PlateThickness") = 12 End If

When you set a parameter, Inventor rebuilds the model immediately. If the model has suppression rules linked to that parameter, those also fire automatically.

Dim vs Parameter() — What's the Difference?

This is one of the most common points of confusion for new iLogic users:

ConceptWhat it isExample
DimA local variable inside your rule. Exists only while the rule runs. Does NOT change the model.Dim x As Double = 100
Parameter()A model parameter in Inventor's parameter table. Persists in the file. Changes the model geometry.Parameter("Width") = 100

⚠️ Common mistake: Using Dim Length = 500 instead of Parameter("Length") = 500. The Dim version creates a local variable — your model doesn't change at all.

Working with String Parameters

Not all parameters are numbers. Inventor also supports text parameters — for storing material names, descriptions, part numbers, and configuration labels:

' Read a text/string parameter Dim material As String = Parameter("Material") ' Write a text parameter Parameter("Material") = "Stainless Steel 316" ' Use string parameter in a condition If Parameter("Environment") = "Offshore" Then Parameter("Material") = "316L SS" Parameter("CoatingSpec") = "Epoxy Marine Grade" End If

Parameter Types in Autodesk Inventor

Inventor has three types of parameters you'll work with in iLogic:

  • Model Parameters — created by sketches and features (e.g. d0, d1). Usually renamed to meaningful names like Length, WallThickness.
  • User Parameters — manually created in the Parameters panel. Used to store configuration values, flags, and calculated results.
  • Reference Parameters — driven by the model (read-only). For example, a mass or bounding box value that Inventor calculates.

💡 Best practice: Always rename your model parameters (d0, d1, d2…) to meaningful names before writing iLogic rules. Rules referencing BeamLength are far more readable than rules referencing d47.

Real-World Example: Beam Size Configurator

Here's a complete iLogic rule that reads a beam size selection and sets multiple parameters automatically:

' Read the beam size selection from a user parameter Dim beamSize As String = Parameter("BeamSize") Select Case beamSize Case "UB203x133" Parameter("BeamDepth") = 203.2 Parameter("FlangeWidth") = 133.4 Parameter("WebThickness") = 6.3 Parameter("FlangeThick") = 7.8 Case "UB254x146" Parameter("BeamDepth") = 256.0 Parameter("FlangeWidth") = 146.1 Parameter("WebThickness") = 6.4 Parameter("FlangeThick") = 10.9 Case "UB305x165" Parameter("BeamDepth") = 308.7 Parameter("FlangeWidth") = 166.8 Parameter("WebThickness") = 5.9 Parameter("FlangeThick") = 11.8 End Select

When the engineer changes BeamSize to any of the listed values, the rule fires and updates all four cross-section parameters at once — the model rebuilds to the correct geometry automatically.

Common Mistakes with iLogic Parameters

  • Wrong case in parameter name — Parameter("length") won't find Length. Check the exact name in your Parameters panel (Manage tab → Parameters).
  • Parameter doesn't exist yet — You must create the parameter in the Parameters panel before you can reference it in a rule. iLogic won't create new parameters automatically.
  • Units mismatch — iLogic works in Inventor's internal units (centimetres for length by default). If your rule sets Parameter("Length") = 500, this may be 500 cm unless units are explicitly handled.
  • Trying to write a Reference Parameter — Mass, surface area, and bounding box values are read-only. You can read them but cannot set them.
  • Forgetting to call iProperties after changing parameters — If your model's iProperties (description, part number) depend on parameters, you may need to trigger an iProperties rule after changing parameters.

💡 Debug tip: Use MsgBox(Parameter("Length")) to print any parameter's current value during development. This instantly confirms whether you're reading the right value.

iLogic Forms: Build Custom Input Dialogs
in Autodesk Inventor

iLogic Forms let you create professional dialog boxes inside Autodesk Inventor — with dropdowns, checkboxes, and text inputs — that drive your automation rules. No external software. No coding degree. Here's everything you need to know.

What Are iLogic Forms?

iLogic Forms are custom dialog boxes that appear inside Autodesk Inventor. They give engineers and operators a clean, simple interface to enter product data — load ratings, materials, dimensions, customer options — which iLogic then uses to automatically configure the 3D model.

Without iLogic Forms, engineers interact with Inventor through the parameters panel or by editing numbers directly in a sketch — which is confusing for anyone who didn't build the model. With Forms, you build a purpose-built UI that hides the complexity and presents only the inputs that matter.

💡 Think of it like this: iLogic rules are the engine. iLogic Forms are the dashboard. The operator just sees the controls — not the wiring behind them.

What Can You Put Inside an iLogic Form?

iLogic Forms support a wide range of input controls, making them flexible enough for almost any engineering configuration task:

  • Text boxes — free-text input for part numbers, descriptions, customer names
  • Numeric inputs — for dimensions, loads, quantities (with optional min/max validation)
  • Dropdowns (ComboBox) — predefined lists of options, e.g. beam sizes, material grades
  • Checkboxes — toggle features on/off, e.g. include lifting lugs, add access platform
  • Radio buttons — exclusive choices, e.g. select frame type: welded / bolted / hybrid
  • Labels and images — annotate the form, add a product diagram, guide the operator
  • Buttons — trigger rules, run calculations, update the model instantly

How to Create an iLogic Form — Step by Step

1

Open the iLogic Browser. In Autodesk Inventor, go to the Manage tab → click iLogic → select iLogic Browser. You'll see two tabs: Rules and Forms.

2

Create a new Form. Click the Forms tab in the iLogic Browser → right-click → Add Form. Give it a clear name like ProductConfigurator.

3

Design the form layout. The Form Designer opens — a drag-and-drop canvas. Drag controls from the left panel onto your form. Each control can be linked directly to an Inventor parameter by right-clicking → Set Parameter.

4

Link controls to parameters. Select a Numeric Input → in the Properties panel, set Parameter Name to the Inventor parameter you want it to drive (e.g. LoadRating). The form now reads and writes that parameter directly.

5

Add an "Update Model" button. Drag a Button control onto the form. Set its action to run your iLogic rule. When the operator clicks it, iLogic fires, reads all form values, and updates the model.

6

Show the form from a rule. In any iLogic rule, call GoTo Form("ProductConfigurator") to open your form. You can trigger this from a button, a model event, or when the document opens.

Real Example: A Product Configurator Form

Here's a practical scenario: you manufacture steel skid frames in three sizes. Instead of an engineer opening Parameters and guessing which values to change, you build this form:

' Rule: Apply configuration when form button is clicked ' The form has a ComboBox named "FrameSize" linked to a custom parameter Dim size As String = Parameter("FrameSize") If size = "Small (2T)" Then Parameter("FrameLength") = 2000 Parameter("FrameWidth") = 1000 Parameter("BeamSize") = "150x75" ElseIf size = "Medium (5T)" Then Parameter("FrameLength") = 3000 Parameter("FrameWidth") = 1500 Parameter("BeamSize") = "200x100" ElseIf size = "Large (10T)" Then Parameter("FrameLength") = 4500 Parameter("FrameWidth") = 2000 Parameter("BeamSize") = "300x150" End If ' Suppress lifting lugs if checkbox is unchecked Feature.IsActive("LiftingLugs") = Parameter("IncludeLiftingLugs") iLogicVb.UpdateWhenDone = True

The operator opens Inventor, sees a clean form with one dropdown and one checkbox, makes their selection, clicks "Update Model" — and Inventor rebuilds the entire frame in seconds. No parameter panel. No risk of editing the wrong value.

Triggering a Form Automatically When a Document Opens

One of the most powerful iLogic Forms features is automatic triggering. You can configure a form to appear every time a document is opened:

' Place this in a rule triggered by the "Document Opened" event ' Go to: iLogic Browser → Rules → right-click → Event Triggers → Document Opened GoTo Form("ProductConfigurator")

Now whenever anyone opens the master assembly, the configurator pops up first. This is the standard approach for engineer-to-order (ETO) workflows — where each project is a variation of a base design.

Validating Inputs Before the Model Updates

iLogic Forms can validate user inputs before running the automation. This prevents errors from reaching the model:

' Check that the user entered a valid load before updating Dim load As Double = Parameter("DesignLoad") If load <= 0 Then MessageBox.Show("Design load must be greater than zero. Please check your input.", "Input Error") Return ' Stop — don't update the model End If If load > 50 Then MessageBox.Show("Load exceeds the maximum capacity of this frame (50T). Contact engineering.", "Warning") Return End If ' Validation passed — proceed with configuration iLogicVb.UpdateWhenDone = True

⚠️ Important: Without input validation, a user entering 0 or a negative number can break model geometry or cause rebuild failures. Always validate before updating.

When Should You Use iLogic Forms?

iLogic Forms are the right choice when:

  • Multiple people use the same Inventor model (not just the designer who built it)
  • Your products have many variants driven by just a few key inputs
  • You want to eliminate configuration errors in your design process
  • You're building a product configurator for sales or project engineers
  • You need to guide operators through a defined input sequence
  • You want to protect the model from invalid or out-of-range inputs

Common iLogic Forms Mistakes (and How to Avoid Them)

Mistake 1: Linking controls to the wrong parameter type

iLogic has two types of parameters: Inventor parameters (dimensions, constraints) and custom iLogic parameters (strings, booleans, custom logic values). Dropdowns for text options must be linked to string-type iLogic parameters, not numeric Inventor parameters. Mixing these causes silent errors where the form appears to work but doesn't update the model.

Mistake 2: Not setting a default value

If a form control has no default value, and the rule runs before the operator fills in the field, you'll get an empty string or zero — which may break the model. Always set sensible defaults in the Form Designer's Properties panel.

Mistake 3: Building the form before the rules are stable

Forms are a presentation layer on top of your rules. If the underlying iLogic rules have logic errors, fixing them after the form is built is harder. Write and test your rules first — then build the form on top.

Mistake 4: Too many controls on one form

Engineers sometimes try to put every possible option on one mega-form. This creates confusion. Break complex configurators into multiple linked forms, or use tab controls inside a single form to organise inputs by category.

What's Next After Learning iLogic Forms?

iLogic Forms are one module in a complete iLogic skill set. Once you can build forms, the natural progression is:

  • Excel integration — read product specs from spreadsheets directly into your forms
  • Assembly automation — use form inputs to configure multiple parts simultaneously
  • Drawing automation — trigger drawing generation and PDF export from a form button
  • BOM export — auto-generate and export Bills of Materials after configuration
  • Email / file output — send the configured model package automatically after form submission

These are advanced capabilities that — when combined — create a fully automated engineer-to-order workflow. A job that used to take a senior engineer half a day can be configured and output in under 10 minutes.

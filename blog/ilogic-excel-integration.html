iLogic Excel Integration: Drive Autodesk
Inventor from a Spreadsheet

Your engineering data already lives in Excel — project specs, product tables, customer requirements. iLogic can read that data directly and use it to configure your Inventor models automatically. No copy-pasting. No manual parameter updates. Here's exactly how it works.

Why Connect iLogic to Excel?

In most engineering companies, the product specification lives in a spreadsheet long before anyone opens Inventor. A sales engineer fills in a project data sheet. A project manager updates a requirements table. The CAD engineer then has to manually translate those numbers into Inventor — dimension by dimension, parameter by parameter.

This translation step is where errors happen. It's also completely unnecessary.

iLogic can read your Excel file directly and drive the Inventor model from it. When the spec changes in Excel, you run one rule — and the model updates to match. No re-entering data. No risk of misreading a number.

✅ Real impact: Engineers who implement iLogic–Excel integration typically eliminate 80–90% of the manual data transfer time on configure-to-order and engineer-to-order projects.

What Can iLogic Read from Excel?

iLogic uses Inventor's built-in iLogicVb.ExcelGetValue method to read any cell from any Excel workbook. You can pull:

  • Dimensions and numeric parameters (lengths, loads, thicknesses)
  • Text strings (part numbers, descriptions, material grades, customer names)
  • Boolean flags (yes/no, include/exclude feature toggles)
  • Lookup table values (beam sizes mapped to load ratings)
  • Entire rows of product variant data

The Excel file can be open or closed — iLogic reads it either way. It can be on the same machine, on a shared network drive, or in a project folder alongside the Inventor files.

Basic iLogic Code: Reading from Excel

Here is the core iLogic syntax for reading values from an Excel file:

' ── Reading values from Excel into Inventor ── ' iLogicVb.ExcelGetValue(FilePath, SheetName, Row, Column) ' Define the Excel file path Dim xlFile As String = "C:\Projects\PRJ-2026-047\ProjectDataSheet.xlsx" Dim sheet As String = "Sheet1" ' Read numeric dimensions from column B Dim frameLength As Double = iLogicVb.ExcelGetValue(xlFile, sheet, 4, 2) Dim frameWidth As Double = iLogicVb.ExcelGetValue(xlFile, sheet, 5, 2) Dim designLoad As Double = iLogicVb.ExcelGetValue(xlFile, sheet, 6, 2) ' Read text strings from column B Dim projectNum As String = iLogicVb.ExcelGetValue(xlFile, sheet, 2, 2) Dim clientName As String = iLogicVb.ExcelGetValue(xlFile, sheet, 3, 2) Dim beamGrade As String = iLogicVb.ExcelGetValue(xlFile, sheet, 7, 2) ' Apply dimensions to Inventor parameters Parameter("FrameLength") = frameLength Parameter("FrameWidth") = frameWidth ' Apply text values to iProperties iProperties.Value("Custom", "Project Number") = projectNum iProperties.Value("Custom", "Client") = clientName iProperties.Value("Summary", "Comments") = "Grade: " & beamGrade iLogicVb.UpdateWhenDone = True

Run this rule once — and Inventor reads all 10 rows, updates the model dimensions, and populates the iProperties. What used to take 15 minutes of careful manual entry takes under 3 seconds.

Advanced: Reading a Feature Toggle (Yes/No)

When Excel contains Yes/No flags that control whether a feature is included in the model, you read the string and convert it to a boolean:

' Read Yes/No flag from Excel and toggle a feature Dim liftingLugsFlag As String = iLogicVb.ExcelGetValue(xlFile, sheet, 8, 2) Dim platformFlag As String = iLogicVb.ExcelGetValue(xlFile, sheet, 9, 2) ' Convert "Yes"/"No" string to feature active/suppressed Feature.IsActive("LiftingLugs") = (liftingLugsFlag.ToUpper() = "YES") Feature.IsActive("AccessPlatform") = (platformFlag.ToUpper() = "YES") ' Also stamp it in iProperties for the BOM iProperties.Value("Custom", "Lifting Lugs") = liftingLugsFlag iProperties.Value("Custom", "Access Platform") = platformFlag

Advanced: Excel as a Lookup Table

One of the most powerful patterns in iLogic–Excel integration is using Excel as a lookup table. Instead of hard-coding beam sizes in your iLogic rules, you store them in Excel — where non-programmers can update them without touching the rule code.

Here's what the lookup table sheet looks like:

A — Load (T) B — Beam Height (mm) C — Beam Width (mm) D — Wall Thickness
1LoadHeightWidthThickness
22150755
352001006
482501258
51030015010
61535017512
72040020016

The iLogic rule reads the design load from the project data sheet, then loops through the lookup table to find the matching row:

' ── Lookup beam size from Excel table ── Dim lookupFile As String = "C:\Standards\BeamSizeTable.xlsx" Dim lookupSheet As String = "BeamSizes" Dim load As Double = designLoad ' from project data sheet above Dim beamHeight As Double = 200 ' defaults in case no match Dim beamWidth As Double = 100 Dim wallThickness As Double = 6 ' Loop through table rows 2–7 (skip header row 1) Dim i As Integer For i = 2 To 7 Dim tableLoad As Double = iLogicVb.ExcelGetValue(lookupFile, lookupSheet, i, 1) If load <= tableLoad Then beamHeight = iLogicVb.ExcelGetValue(lookupFile, lookupSheet, i, 2) beamWidth = iLogicVb.ExcelGetValue(lookupFile, lookupSheet, i, 3) wallThickness = iLogicVb.ExcelGetValue(lookupFile, lookupSheet, i, 4) Exit For ' found the right row — stop looping End If Next ' Apply to model Parameter("BeamHeight") = beamHeight Parameter("BeamWidth") = beamWidth Parameter("WallThickness") = wallThickness

Now when your structural engineer updates the beam size table in Excel — adding a new load rating, changing a wall thickness — the iLogic rule automatically picks up the new values next time it runs. No one needs to touch the iLogic code.

Writing Data Back to Excel

iLogic can also write data back to Excel — not just read from it. This is useful for generating reports, populating BOM summaries, or creating a project log every time a model is configured:

' ── Write calculated results back to Excel ── ' iLogicVb.ExcelPutValue(FilePath, SheetName, Row, Column, Value) Dim reportFile As String = "C:\Projects\PRJ-2026-047\ModelReport.xlsx" ' Write confirmation data to the report sheet iLogicVb.ExcelPutValue(reportFile, "ModelData", 2, 2, Parameter("FrameLength")) iLogicVb.ExcelPutValue(reportFile, "ModelData", 3, 2, Parameter("FrameWidth")) iLogicVb.ExcelPutValue(reportFile, "ModelData", 4, 2, beamHeight) iLogicVb.ExcelPutValue(reportFile, "ModelData", 5, 2, beamWidth) iLogicVb.ExcelPutValue(reportFile, "ModelData", 6, 2, "Configured: " & Now()) iLogicVb.UpdateWhenDone = True

After the rule runs, the Excel report is automatically updated with the final model dimensions and a timestamp. This creates a complete audit trail of every configuration — useful for revision control and client documentation.

Best Practices for iLogic–Excel Integration

Use named ranges, not hardcoded row numbers

If your Excel file uses named ranges (e.g. FrameLength instead of row 4 column 2), your iLogic code becomes far easier to maintain. If a row is added to the spreadsheet, code referencing row numbers breaks — named ranges don't.

' Better: read by named range using a helper function ' ExcelGetValueByName(FilePath, SheetName, NamedRange) Dim frameLength As Double = iLogicVb.ExcelGetValueByName(xlFile, sheet, "FrameLength")

Store the file path as a relative reference

Hardcoding C:\Projects\... breaks when the project moves to a different machine or shared drive. Store the Excel path in an iLogic parameter so it can be updated once per project without touching the rule code.

Handle missing or empty cells gracefully

If a cell is empty, iLogicVb.ExcelGetValue returns an empty string or zero — which can silently set a dimension to zero and crash the model rebuild. Always validate before applying:

Dim rawLength = iLogicVb.ExcelGetValue(xlFile, sheet, 4, 2) If rawLength = "" Or rawLength = 0 Then MessageBox.Show("Frame Length cell is empty in the data sheet. Please check row 4.", "Missing Data") Return End If Parameter("FrameLength") = rawLength

Keep the Excel file closed when iLogic reads it

iLogic can read Excel files whether they're open or closed. But if two users have the file open simultaneously (common on shared drives), you can get file-lock errors. Structure your workflow so the data sheet is saved and closed before running the iLogic rule.

⚠️ Avoid this: Never store the Excel data file inside the same folder as your Inventor master template. If the template is copied for a new project, the data sheet comes with it and points to stale data. Keep data sheets in project-specific folders.

iLogic + Excel + Forms: The Complete Automation Stack

The most powerful iLogic workflows combine all three tools together:

  1. Excel stores the project data and lookup tables (the data layer)
  2. iLogic Forms provides a clean UI for the operator (the interface layer)
  3. iLogic Rules reads Excel, applies the data, updates the model (the logic layer)

The operator sees only the Form. The Form triggers the Rule. The Rule reads Excel. Inventor rebuilds. A drawing comes out. The operator doesn't need to understand any of it — they just fill in the form and click "Generate".

This is what a fully automated engineer-to-order CAD workflow looks like in practice. It replaces hours of manual work with a process any team member can operate — not just the engineer who built it.

iLogic iProperties: Auto-Fill Part Numbers,
Title Blocks & BOM Data

Manually filling iProperties — part numbers, descriptions, materials, revision numbers — is one of the biggest time sinks in Autodesk Inventor. iLogic can populate all of it automatically, consistently, across every part in your assembly.

What Are iProperties?

iProperties are metadata fields attached to every Autodesk Inventor file. They store information like part number, description, material, revision, author, project, and any custom fields your company defines. This data flows automatically into drawing title blocks, Bills of Materials, and PDM/PLM systems.

The problem is that iProperties are normally filled manually — file by file, field by field. On a complex assembly with 200 parts, filling iProperties manually takes hours and introduces errors. iLogic eliminates this entirely.

💡 Why iProperties matter for your BOM: If iProperties aren't filled correctly, your Bill of Materials will have blank descriptions, missing part numbers, and wrong materials. Your drawings will have incomplete title blocks. iLogic is the solution.

Basic Example: Set iProperties from Parameters

The most common use case is driving iProperties directly from your model's parameters — so when dimensions change, the description and part number update automatically:

' ── Auto-fill iProperties from model parameters ── ' Read parameters from the model Dim length As Double = Parameter("FrameLength") Dim width As Double = Parameter("FrameWidth") Dim load As Double = Parameter("DesignLoad") Dim grade As String = Parameter("SteelGrade") ' Build a structured description automatically iProperties.Value("Project", "Description") = _ "Skid Frame " & length & "x" & width & "mm - " & load & "T - " & grade ' Build a part number from project parameters Dim projNum As String = Parameter("ProjectNumber") iProperties.Value("Project", "Part Number") = projNum & "-SF-001" ' Set standard fields iProperties.Value("Project", "Revision Number") = "A" iProperties.Value("Physical", "Material") = "Steel, " & grade iProperties.Value("Summary", "Company") = "CAD Automator Ltd" iProperties.Value("Summary", "Author") = "Engineering Dept" iLogicVb.UpdateWhenDone = True

Auto-Fill iProperties Across an Entire Assembly

The real power comes when you loop through every component in an assembly and update iProperties on all of them at once. This is how you populate an entire BOM in one click:

' ── Loop through all components and fill iProperties ── Dim oDoc As AssemblyDocument = ThisDoc.Document Dim oComp As ComponentOccurrence For Each oComp In oDoc.ComponentDefinition.Occurrences Dim oPartDoc As Document = oComp.Definition.Document ' Skip sub-assemblies — only process parts If oPartDoc.DocumentType = kPartDocumentObject Then ' Set company and revision on every part oPartDoc.PropertySets.Item("Summary Information").Item("Company").Value = "CAD Automator Ltd" oPartDoc.PropertySets.Item("Design Tracking Properties").Item("Revision Number").Value = "A" ' Save each part after updating oPartDoc.Save() End If Next MessageBox.Show("iProperties updated on all parts in the assembly.", "Done")

Linking iProperties to the Drawing Title Block

Once iProperties are filled, your Inventor drawing title block can pull them in automatically — no manual entry in the drawing at all. Here's how to set it up:

  1. In your drawing template, double-click the title block to edit it
  2. Select a text field (e.g. "Part Number") → right-click → Edit Field Text
  3. Choose Properties — Model → select the matching iProperty (e.g. Part Number)
  4. Repeat for Description, Material, Revision, Author
  5. Save as your company drawing template

From now on, every drawing made from a model with correctly filled iProperties will have a complete, accurate title block — automatically. Zero manual entry.

✅ Pro tip: Combine this with the iLogic rule above. Run the rule when the model is finalised → iProperties fill → open the drawing → title block is already complete. The entire documentation step is automated.

Reading iProperties (Not Just Writing)

iLogic can also read iProperties — useful for building logic based on existing metadata:

' Read iProperties into variables Dim currentRev As String = iProperties.Value("Project", "Revision Number") Dim currentPN As String = iProperties.Value("Project", "Part Number") Dim currentMat As String = iProperties.Value("Physical", "Material") ' Use them in logic — e.g. only update if revision is still "A" If currentRev = "A" Then ' Still in preliminary design — allow auto-updates iProperties.Value("Project", "Description") = "PRELIMINARY - " & currentPN Else ' Issued drawing — warn before overwriting MessageBox.Show("Warning: This part is at Rev " & currentRev & ". Are you sure you want to update iProperties?") End If

Creating Custom iProperties

Autodesk Inventor lets you add your own custom iProperties beyond the built-in ones. These are perfect for project-specific data — customer name, purchase order number, surface finish, weld inspection status:

' Create and set a custom iProperty ' If the property doesn't exist yet, iLogic creates it automatically iProperties.Value("Custom", "Customer") = "Precision Parts Ltd" iProperties.Value("Custom", "PO Number") = "PO-2026-1042" iProperties.Value("Custom", "Surface Finish") = "Hot Dip Galvanised" iProperties.Value("Custom", "Weld Standard") = "AWS D1.1" iProperties.Value("Custom", "Inspection Date") = Now().ToString("dd-MMM-yyyy")

These custom properties then appear in your BOM automatically — making the Bill of Materials a complete document with all project-specific data, not just basic part information.

Common iProperties Mistakes to Avoid

Using the wrong category name

The category names in iLogic must match exactly. The most common mistake is using "Project" when the property is actually in "Design Tracking Properties". If you get a "property not found" error, open the iProperties dialog in Inventor and check which tab the property is on — that's the category name.

Not saving after updating

iProperties set by iLogic are in memory until the file is saved. If you close without saving, the iProperties revert. Always call ThisDoc.Document.Save() at the end of any rule that modifies iProperties, or remind the user to save.

Overwriting iProperties on released parts

If your company uses a PDM system (like Vault), iProperties on released/checked-in parts may be locked. Check the document's checkout status before writing to avoid silent failures or access errors.

⚠️ Watch out: iLogic can only write iProperties on files that are not write-protected. If Inventor shows the file as read-only, the rule will appear to succeed but the properties won't actually be saved.

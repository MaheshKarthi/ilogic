iLogic Drawing Automation: Auto-Generate
Views, Title Blocks & PDFs

Manually updating drawing title blocks, adjusting views, and exporting PDFs after every design change is one of the most time-consuming tasks in Autodesk Inventor. iLogic eliminates it. This guide shows you exactly how to automate your entire drawing workflow.

What Can iLogic Automate in Drawings?

iLogic has full access to Inventor's drawing environment. From a single rule, you can:

  • Auto-fill title block fields (drawn by, checked by, revision, date, project number)
  • Open associated drawing files from the part or assembly
  • Export drawings as PDF, DWG, or DXF files automatically
  • Set drawing sheet scale based on model size
  • Update revision tables when model parameters change
  • Batch-export an entire project's drawings in one click
  • Print drawings directly to a network printer

💡 The biggest win: Trigger drawing export automatically when the model is saved — so every design iteration produces an up-to-date PDF without any manual steps.

Auto-Fill the Title Block

The most common use of iLogic in drawings is automatically populating title block fields from the model's iProperties. This eliminates manual data entry and ensures the drawing always matches the model:

' This rule runs in the drawing file (.idw) ' It reads iProperties from the referenced part and fills the title block Dim oDoc As DrawingDocument = ThisDoc.Document Dim oSheet As Sheet = oDoc.ActiveSheet Dim oTitleBlock As TitleBlockDefinition = oSheet.TitleBlock ' Get the referenced model document Dim oRefDoc As PartDocument = oDoc.ReferencedDocuments.Item(1) ' Read iProperties from the model Dim partNum As String = iProperties.Value(oRefDoc.FullFileName, "Project", "Part Number") Dim description As String = iProperties.Value(oRefDoc.FullFileName, "Summary", "Description") Dim material As String = iProperties.Value(oRefDoc.FullFileName, "Physical", "Material") ' Write to title block prompts iProperties.Value("Drawing", "Title") = description iProperties.Value("Drawing", "Part Number") = partNum iProperties.Value("Drawing", "Material") = material iProperties.Value("Drawing", "Date") = Now.ToString("dd-MMM-yyyy")

Open a Drawing File from iLogic

If you want to trigger drawing operations from the part or assembly file, first open the associated drawing:

' Build the drawing file path (same folder, same name, .idw extension) Dim modelPath As String = ThisDoc.Document.FullFileName Dim drawingPath As String = System.IO.Path.ChangeExtension(modelPath, ".idw") ' Check if the drawing exists before opening If System.IO.File.Exists(drawingPath) Then Dim oDrawDoc As DrawingDocument = ThisApplication.Documents.Open(drawingPath) ' Now you can work with oDrawDoc Else MsgBox("Drawing file not found: " & drawingPath) End If

Export Drawing to PDF Automatically

Exporting a PDF from a drawing file is one of the most useful iLogic automations. Here's the complete code:

' Export the active drawing to PDF Dim oDoc As DrawingDocument = ThisDoc.Document ' Build the output PDF path (same folder as drawing) Dim drawingPath As String = oDoc.FullFileName Dim pdfPath As String = System.IO.Path.ChangeExtension(drawingPath, ".pdf") ' Set up the PDF export options Dim oPDFExporter As PDFExportOptions = ThisApplication.TranslatorAddIns.ItemById("{0AC6FD96-2F4D-42CE-8BE0-8AEA580399E4}") ' Export all sheets to a single PDF Dim oContext As TranslationContext = ThisApplication.TransientObjects.CreateTranslationContext() oContext.Type = IOMechanismEnum.kFileBrowseIOMechanism Dim oOptions As NameValueMap = ThisApplication.TransientObjects.CreateNameValueMap() oOptions.Value("ExportFileType") = "PDF" oOptions.Value("AllColor") = True oOptions.Value("OpenAfterExport") = False Dim oData As DataMedium = ThisApplication.TransientObjects.CreateDataMedium() oData.FileName = pdfPath oPDFExporter.SaveCopyAs(oDoc, oContext, oOptions, oData) MsgBox("PDF saved: " & pdfPath)

Batch Export Multiple Drawings

For projects with many drawings, you can loop through an entire folder and export every .idw file to PDF in one operation:

' Batch export all .idw files in a folder to PDF Dim drawingFolder As String = "C:\Projects\MyProject\Drawings\" Dim files() As String = System.IO.Directory.GetFiles(drawingFolder, "*.idw") For Each filePath As String In files Dim oDrawDoc As DrawingDocument = ThisApplication.Documents.Open(filePath, False) Dim pdfPath As String = System.IO.Path.ChangeExtension(filePath, ".pdf") ' Export to PDF (same code as above) ' ... (PDF export code here) oDrawDoc.Close(False) Next MsgBox("Batch export complete. " & files.Length & " drawings exported.")

💡 Pro tip: Pass False as the second argument to Documents.Open() to open the drawing silently (without displaying it). This makes batch operations much faster.

Trigger Drawing Updates on Model Save

The most powerful setup is a rule that fires every time the model is saved — automatically updating the drawing and exporting a PDF without any manual steps:

' Place this rule in the model file with trigger: "On Save" ' It will auto-export the drawing PDF every time the model is saved Dim modelPath As String = ThisDoc.Document.FullFileName Dim drawingPath As String = System.IO.Path.ChangeExtension(modelPath, ".idw") If System.IO.File.Exists(drawingPath) Then Dim oDrawDoc As DrawingDocument = ThisApplication.Documents.Open(drawingPath, False) ' Update title block iProperties first iProperties.Value(drawingPath, "Drawing", "Date") = Now.ToString("dd-MMM-yyyy") ' Save the drawing oDrawDoc.Save() ' Export PDF (insert PDF export code here) oDrawDoc.Close(False) End If

Real-World Example: Full Auto-Drawing Rule

Here's a practical scenario: an engineer changes a beam size in the model, and iLogic automatically:

  1. Updates all model parameters
  2. Opens the drawing file
  3. Updates the title block (part number, description, date, revision)
  4. Saves the drawing
  5. Exports a PDF to the project's output folder
  6. Closes the drawing

This entire sequence runs in under 10 seconds — what used to take 15–20 minutes of manual work.

⚠️ Important: Drawing automation rules that open and close files are best set to trigger manually (via a button) or on model save — not on every parameter change. Opening files mid-edit can cause unexpected behaviour.
